## 0. 这件事要解决什么

认可这个形态，要求把清单里其余条目照此补齐。

```

  corpus\            ← 原始材料：slides/ notes/ transcripts/ subtitles/
```

### 为什么是这个结构（否决的两个替代）

- **每门课整套复制 CS234 目录**：起步快，但十份工具各自走样，修一个 bug 改十遍。
  ML 那边已经因此断过一次构建。
- **所有内容塞进一个大 course.json**：入口只有一个，但书与课形状不同，
  各课自测记录会混在一起（`localStorage` 键按课程 id 前缀隔离，合并即失效），
  入口会退化成一张 160 行的长表。

## 4. 精读页设计

**基线是 ML 那一版**（用户 2026-09-28 明确认可的形态），不是 CS234 当初的暗色版。

### 4.1 版面与主题

- 左栏原件 PDF（`<iframe src="PDF?p=N#page=N&view=FitH">`），右栏讲解 + 自测，**一次只出现一页的信息**。
- **浅色纸感为默认**，☾ 可切暗色，`localStorage` 记忆。用户原话：
  「放映厅可以用黑色，可是平时能不能不用这个颜色，看字看不清楚」。
- 色值用 ML 那边 WCAG 实测过的一套（`--ink:#23272C`、`--acc2:#845808` 等），
  四种表面（纸底 / 卡片白 / 凹陷 / 高亮）均 ≥4.5:1。

**⚠ 两条产品线目前是分叉的，合并有已知缺口**：CS234 的 `coursekit/reader_template.html`
**是纯暗色的**（实测 `themeBtn` 出现 0 次、`data-theme` 0 次），浅色主题只存在于
ML 的 `精读/theme.py`。而 CS234 那边后来新增的 `.res` 科研格用了
`#3b2f4f` / `#b98fe6` 两个颜色，**不在 `theme.py` 的 `HARDCODED` 映射表里** ——
直接套用会得到一个在浅色下依然深紫的框。合并时必须补齐，并逐元素跑对比度审计。

### 4.2 内容字段

沿用 ML 加深后的字段集，**新增两个**：

| 字段 | 内容 | 来源 |
|---|---|---|
| `t` / `one` / `pts` / `eq` | 论点式标题、一句话结论、要点、公式 | 既有 |
| `quote` | 课件英文原话（灰色左条） | 既有 |
| `tbl` | 表格（对比表 / 情况表 / 数值表 / 符号表） | 既有 |
| `say` | 讲稿里说了而课件上没有的话 | 既有 |
| `tip` | 陷阱、记号冲突 | 既有 |
| `res` | **「科研连接」** —— 与论文的联系，带三档出处标注（已核 / 推断 / 待核）与 `ref` 出处 | 既有 |
| **`link`** | **「你学过的对应」** —— 链到 CS234 的片子或精读。例：CS224R 策略梯度 → CS234 L08 | **新增** |

**2026-09-29 核查修正**：设计初稿提出新增一个 `paper` 字段放「与论文的联系」。
实地读 `coursekit/reader_template.html` 后发现**它已经存在**，叫 `res`（科研连接），
而且比初稿的设想更完整 —— 带三档出处标注（`已核` / `推断` / `待核`，与
`research/00-BRIEFING` 的原始标注一致，`build_reader.py` 的 `check_res()` 会校验档位）
与 `ref` 出处栏，另有讲级粒度的「科研主线」卡（`_course.load_thread()`）。
**沿用 `res`，不新造 `paper`。** 真正新增的只有 `link` 一个字段。

渲染顺序（**2026-09-30 按模板实况修正**）：
`quote → one → eq → pts → tbl → say → link → tip → res`

初稿写的是「…say → link → res → tip」，与模板不符 —— 模板里 `tip` 在 `res` 之前。
`link` 插在 `say` 与 `tip` 之间：`say`（讲稿里补的）与 `link`（你学过的对应）
都是「别处说过的话」，`tip`（陷阱）与 `res`（科研连接）是更尖的提示，放最后。

CSS 类名用 **`.lnk`** 而不是 `.link` —— 后者容易和 HTML 的 `<link>` 元素选择器混淆。

### 4.3 密度标准

**2026-09-30 实测校正 —— 初稿的数字是错的，因为混了两种度量。**

初稿写「每页 ≥1200 字」，依据是记忆里 ML 加深后「每页 1663 字」。实际拿
`build_reader.py` 的 `wordcount()`（剥 HTML 标签后，中文按字、拉丁按词、数字成串）
量了用户认可的那三份 ML 精读：

| | 闸门度量 | 含标签的原始字符 |
|---|---|---|
| M2T1 | **632 词/页** | 1508 /页 |
| M2T2 | **603 词/页** | 1421 /页 |
| M2T3 | **603 词/页** | 1483 /页 |

**「1663 字」量的是含 HTML 标签的原始字符，不是内容密度。** 两者差约 2.4 倍，
初稿把前者当成后者，于是定了一个比实际标准高一倍的门槛。

**本项目的门槛：`_目标.密度 = 600`**（闸门度量，与 ML 实际达到的持平）。
风格照那八条质量标准（论点式页标题、表格密集、引课件原话、讲「为什么」、
手算例带验证步、抓本课特有约定、指出材料内部不一致、明说不考什么）。

### 4.4 自测与防泄题

- `quiz` 的键必须是某条 `notes` 的**起始页**，否则题永远显示不出来（`build_reader.py` 自检）。
- **选项里一律不许出现 `<b>`**（题干与解析里可以）。
- 出片前扫**答案位置分布**，用固定种子打散并按文本回写 `a`。
  ML 那边 50 题有 48 题答案在 B，闭眼选 B 即满分。
- 错题本规则写在面板上：**连着答对两次就毕业**。

### 4.5 书的精读（与课不同）

**一条讲解覆盖一节（2–5 页），不逐页写。** `notes` 的 `r:[起,止]` 本来就支持区间。

理由：书一页的信息量约为课件一页的五倍。逐页写的话，仅 Lattimore 一本就要 500 余条。
用户 2026-09-29 确认「书按节写」。

### 4.6 没有讲稿的课（CSE 541、6.S890）

`say` 字段的原定义是「讲稿里说了而课件上没有的话」。这两门无录像无讲稿，
**`say` 改放「补推导」** —— 把讲义里跳过的证明步骤补上。这正是这两门最需要的东西。

## 5. 放映厅设计

- **完全沿用现有引擎与规则**，不新造：R1–R12、六拍结构、动画契约、版面常数、事故实录。
- **保持暗场**（片子是暗的，阅读页是浅的，这个分工是用户定的）。
- 每部片开工前必须填满规格表，**`WRONG MODEL` 一栏为空不许动手**。
- 图元多样度闸门：单个整图级图元 ≤25% 有图镜；不同画法 / 有图镜 ≥0.30。
- 单部片镜数 ≤80（引擎的 `go()` 无 try/catch 地重放全部前序镜，超了会 O(n²) 且一错砖掉半部）。

### CS336 的左栏形态（待定，第一讲时决定）

CS336 的课件多为可执行 Python（`lecture_*.py` 生成 JSON trace），只有部分在

② 把 trace 渲染成 PDF；③ 左栏改放代码而非 PDF。**第一讲动手前实地看过再定**，

## 6. 工作方式

### 6.1 做的顺序

| 步 | 内容 |
|---|---|
| S0 | 基建：抽 `_kit`、建 `plan.json` / 总清单页 / `任务清单.md` |
| S1 | CS224R：下全部 19 份课件与字幕 → 做 **L05 精读 + 放映厅样板** → **停，等用户看** |
| S2 | 条目 1（CSE 541 + Lattimore + 3 篇论文）—— 用户 10–11 月的主线 |
| S3 | CS224R 其余 18 份精读 + 4 部片子 |
| S4–S11 | 条目 2 → 3 → 4 → 6 → 7 → 8 → 9 → 10 |

排序依据是用户的学习时间表：条目 1 是 10–11 月主线，2 和 3 赶 12 月，
6–8 在 2027 年第一学期，9 和 10 殿后。

### 6.2 样板闸门（R7 的推广）

**每种新形态的第一份做完就停，等用户确认后再铺开。** 四处：

1. **CS224R L05** —— 总样板（精读 + 放映厅）
2. **书的第一章** —— 按节写是新形态
3. **CSE 541 第一讲** —— 无讲稿、`say` 改补推导是新形态
4. **CS336 第一讲** —— 左栏形态未定

### 6.3 实施计划的边界

**本设计覆盖十个条目，但一份实施计划只覆盖 S0 + S1**（基建 + CS224R L05 样板）。

理由：样板闸门（§6.2）要求 L05 做完就停。在用户看过样板之前，为其余条目写详细步骤
是在给一个可能要改的格式写实施细节。**每个子项目在轮到它时单独出一份实施计划**，
共用本设计文档作为总纲。

### 6.4 每个子项目的流程

1. **摸底**：下载原件到 `corpus/`，写 `来源.md`（出处、许可、版本、抓取日期）。
2. **先读完全部原件**（R1）：抽逐页文本与讲稿，每讲列一份「要守住的数字」清单。
3. **精读**：逐讲写 → 生成 → 检查（`check_reader.js` 25 条断言 + 防泄题扫描 +
   字数门槛 + 对比度审计）。
4. **放映厅**：填规格表 → 写 episodes → 组装 → 跑全部既有检查。
5. **收尾**：重建课程入口与总清单，更新 `任务清单.md`。

### 6.5 `任务清单.md`

- 顶部一行：现在在做什么、下一步、在等用户确认什么。
- 下面每个子项目一节，逐讲打勾（精读 / 放映厅 / 检查）。
- **每次会话开头先读，结束前更新，做完一项当场勾掉。**
- 另存一条记忆指向此文件，保证新会话能接续。

### 6.6 验证纪律

继承 R9 与规矩 B：**动画的运动过程在本环境无法验证**（无头环境里 `requestAnimationFrame`
不触发，d3 过渡全部停在起始帧）。能静态保证的已全部转成脚本检查；
**运动效果只能由用户在真实浏览器里过一遍**，交付时明确写出哪些部分未经验证，
不许把「无法验证」写成「已通过」。

## 7. 明确不做的 / 风险

### 不做

- **不部署到服务器**。材料含课件原件，本地使用最稳妥；用户需要时再说。
- **不替用户写验收代码**（如 Kuhn poker 上的 CFR）。那是给用户的练习，
  清单页上只放题目与勾选框。

### 风险与预案

| 风险 | 预案 |

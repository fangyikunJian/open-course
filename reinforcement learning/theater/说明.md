## ⚠ 一件无法在本地脚本里验证的事

**动画的运动过程验证不了。** 实测确认：无头/隐藏的预览环境里 `requestAnimationFrame`
根本不触发（700ms 内 0 次），连一个不经本项目代码的**纯 d3 对照探针**也不动。
d3 过渡靠 rAF 驱动，所以在那种环境里所有 `morphBars` / `fillBars` / `trace` 都停在起始帧。
（`setEq` 能验证，是因为 MathJax 走 DOM 而非 rAF。）

所以：**动画效果只能靠你双击本地文件、在真实浏览器里过一遍。**
能静态保证的部分已经全部转成了脚本检查——两端柱高、顶格削平、watch 是否存在。

## 引擎：改了什么，没改什么

`src/eng.txt` 是从 ML 版**原样拷过来**的（含你 2026-09-07 修的两个 bug：本地打开中文乱码、
后台标签页大字残留）。**没有直接改动它**——所有扩展都在 `src/build_common.py` 里以补丁形式
施加，幂等，重跑安全。这样 ML 那边若更新了引擎，拷过来即可，补丁照样生效。

补丁做两件事：

1. **导出图层句柄**。原引擎只导出高层绘图函数，RL 图元需要直接往画布加元素。
   `gS`/`gN` 在 `clearScene` 里只被清空、从不重新赋值，所以直接传选择集是安全的。

2. **RL 图元包**。原工具箱是为 ML 做的（散点 + 拟合线 + 矩阵）。统计了 13 讲共 103 个动画
   候选点后，现有工具只覆盖 47 个，其余需要 RL 专用图元：

   | 图元 | 用途 | 覆盖候选点 |
   |---|---|---|
   | `gridworld(o)` | 格子世界：值 / 策略箭头 / 高亮 / 墙 | 15 |
   | `errbar(o)` | 误差棒、置信区间（UCB 那类） | 7 |
   | `backup(o)` | Sutton&Barto 回溯图：状态圆 + 动作点 | 6 |
   | `tree(o)` | 搜索树，`upto` 控制画到第几个节点（MCTS 增长） | 3 |
   | `mdpChain(o)` | 一维状态链（Mars rover 那种） | — |
   | `bars(o)` | 每状态一根值条（值函数可视化） | — |
   | `arrow(...)` | 带箭头的线，可给弧度 | 多处 |
   | `lamps(o)` | 指示灯排（范式对比） | — |

   **配色语义与 ML 版严格一致**，没有另起一套——你自己写过理由：学习者会形成条件反射。
   蓝 = 模型/输入 · 黄 = 注意力/结论 · 绿 = 正确/答案 · 珊瑚 = 误差/错误 · 紫 = 强调。

## 两条硬规矩（2026-09-09 定下）

**一、字号不许自造。** SVG 标签一律用引擎的 `.slbl`（14px），层级**只靠颜色区分**。
引擎原有的标签体系其实只有 `.axlbl` 13px / `.slbl` 14px / `.celltx` 15px 三档，几乎是一档；
ML 版从不改字号就是这个原因。第一版 L01 里我自造了 `.slbl.big` 19px 和 `.slbl.sm` 11.5px，
结果一屏混着 11.5 / 14 / 19，每次切镜画面都「跳」一下。现在 `sm` / `big` 只保留为颜色别名。

**二、动画只承载动感，不承载信息。** 持续动画全部用 CSS 关键帧（`@keyframes rl-*`），
不用 `setTimeout`：元素被 `clearScene` 移除时动画自动消失，无需 JS 记账，也不会像定时器
那样在后台标签页里卡死——这正是你上次修 `visibility` 那个 bug 的教训。
**后台标签页会暂停关键帧动画，所以任何一帧停住画面都必须是完整的。**

持续动画图元：

| 图元 | 效果 |
|---|---|
| `flow(x1,y1,x2,y2,cls,bend,slow)` | 带**行进虚线**的箭头，持续显示流向 |
| `walker({d,dur,r,cls,label,bob})` | 沿路径无限行进的小车（CSS `offset-path`） |
| `sweepMark({xs,y,dur,back,cls,r})` | 高亮圈沿给定位置无限扫过（表示 DP 扫描方向） |
| `ping(x,y,r,cls)` | 原地扩散的雷达环 |
| `loopArrows({x1,y1,x2,y2,dur})` | 智能体—世界回路上两个持续循环的信号点 |
| `breathe(sel)` / `bob(sel)` / `glow(sel)` | 给已有元素挂呼吸 / 上下浮动 / 发光 |

L01 现状：**39 镜全部含持续动画**，共 73 处循环调用。
验证过 `clearScene()` 后正在运行的动画数归零（无泄漏）。

## 内容标注规则

沿用 `CONTENT-AUDIT.md` 的三分法，因为这次是学术用途，多加了一档：

- **【原课】** CS234 W2019 讲座 + 官方 slides 明确讲过；
- **【补课】** 课上只陈述未证、或干脆没提，由片子补上 —— 讲解里会写明「补课」二字；
- **【记号】** CS234 与 Sutton & Barto 约定不一致处的提示。

第三档不是小事：13 讲共统计出 **165 条记号陷阱**，其中 18 条是与 Sutton & Barto 的约定冲突
（最典型的是回报下标：CS234 写 rₜ+γr_{t+1}+…，S&B 写 R_{t+1}+γR_{t+2}+…，差一位），
另有 **32 条是自动字幕转写错误**。所以有一条硬规矩：

> **凡是要进片子的数学陈述，必须与官方 slides 或 Sutton & Barto 对齐后才落笔。
> 字幕只作为「讲解思路」的来源，不作为公式来源。**

L01 里另有一处需要留意：Mars rover 的动力学是**明确写死的教学用设定**（向右以 0.5 成功、
否则原地），讲座对细节说得较松。片中数值（含临界 γ\* ≈ 0.7737）是按这个设定精确求解的，
不是讲座数字的逐字复刻——片子里也这么标了。

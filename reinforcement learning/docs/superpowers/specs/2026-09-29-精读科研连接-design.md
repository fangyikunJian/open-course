# CS234 精读页 · 理解导向 + 科研连接 · 设计

> 定稿 2026-09-29。用户已批准。
> 上游文档：`skills/PROJECT-SKILL-放映厅.md`（引擎不变量与事故实录）、`coursekit/README.md`（精读站硬规矩）、`skills/evidence.md`（研究依据）。
> 本文件只管精读页这一种交付物。放映厅的片子不在范围内，不动。

## 0 · 一句话

把 CS234 精读页从「每页一句结论加两三条要点」加厚到 ML 版那种密度，**去掉全部备考机制**，并按页/按讲两种粒度接上用户的科研课题（AFlow 内的 node-level fidelity assignment）。

## 1 · 需求的来源与边界

用户的原话与推论：

| 用户说的 | 落到设计上 |
|---|---|
| 「我不需要考试交付」「去除掉任何考试相关的东西」 | 删备考外壳（§4）。**但自测保留**——用户明确选了「保留自测，去掉备考外壳」 |
| 「我的需求是理解知识点」 | 自测题从「定义是什么」改成「机制 / 为什么 / 边界」（§4） |
| 「放映厅做的很好」 | **放映厅不动。** 本 spec 不碰 `theater/` |
| 「学习 ML 那个左边 ppt 右边讲解的模式」 | 实测后确认用户指的是**厚度与字段**，不是版式：RL 现有精读 65–95 词/页，ML 版 624–652 词/页，差 7–8 倍，且 ML 多 `quote`/`tbl`/`exam` 三个字段（§2 §5） |
| 「联系我科研相关的目的」「科研的内容最开始发给你了」 | 科研层，内容源是 `research/00-BRIEFING-给科研的即时结论.md` 与 `research/bridge-threads.json`（§3） |
| 「先加厚，然后补齐全部的」 | 分期 A→B，终态 15 讲全覆盖（§7） |

**明确不做**：备考包、考前走查、模拟卷、错题排名、间隔重复毕业制。这些是 ML 版有而本项目刻意不要的东西。

**本 spec 的范围与实施计划的范围不同。** 本文件描述整个计划（A0 + A1 + B，§7），因为格式决策必须一次定完才不会反复返工。但**实施计划只覆盖 A0**；A1 与 B 各自另起一份 plan，且都以 A0 的实测结果为输入——A0 跑完才知道 400 词/页 是不是一个现实的目标。

## 2 · 现状实测（所有后续判据的基线）

密度，按「CJK 单字 + 拉丁单词 + 数字」计数、剥掉 HTML 标签后：

| | 条数/页数 | 词/页 | 字段 |
|---|---|---|---|
| RL `L01`–`L10` | 19–52 条 / 36–78 页 | **65 – 95** | `r t star one eq pts say tip` |
| ML `M2T1`–`M2T3` | 16–18 条 / 16–18 页 | **624 – 652** | 同上 ＋ `quote` `tbl` `exam` |

文件体积换算：ML 每 1000 词约 **7.2 KB**。L01 加厚到 400 词/页 × 78 页 ≈ 31,200 词 ≈ **223 KB 单文件**。放映厅在 150 KB 单文件上撞过墙（「改一处就要整体重写，风险和成本都不对」），所以精读这边必须分片（§6）。

已确认**不存在**的东西，不必清理：CS234 精读的 schema 里没有 `exam` 字段，全库「考试」二字只出现 1 次，是课件自己的课务（`L10.json` 第 35–36 页「下一次：期中考试」）。备考包装全在 ML 侧，不会跟过来。

## 3 · 科研层：两种粒度（方案 B）

用户在三个方案里选了 B。依据是内容源本身的形状：`bridge-threads.json` 的 `pitfalls`（每线 12–13 条）与 `reviewer_ammunition`（每线 12–13 条）**是讲级的**，`direct_application`（每线 8–10 K 字）才是可逐页切开的。两种粒度本来就存在，压成一种会丢东西。

### 3.1 页级：note 的 `res` 字段，可缺省

```jsonc
"res": {"tag": "已核", "v": "…", "ref": "简报 §4a"}
```

**只在真有连接时出现。** L04（SARSA/Q-learning 细节）与 L06（CNN 结构、DQN 三改进）预期整讲留空，不凑。凑出来的连接比没有连接更坏——它会让人以后分不清哪条是真的。

各讲连接强度的预判（A1/B 落地时逐讲复核，不是承诺）：

| 讲 | 连接 | 强度 |
|---|---|---|
| L15 | OPE / IS / WIS / DR / FQE / 高置信离策略评估 / ESS —— 简报 4a–4e 卡住的全部问题 | 最强（Thread 0 整条） |
| L11–L13 | 老虎机、regret、纯探索、PAC；审稿人第 2 拳（线性可实现性）即 L13 内容 | 强（Thread 1 整条） |
| L16 | UCT 与 UCB1 的来源、drifting-bandit 一致性；论证「AFlow 不是 UCT」 | 强（Thread 2 整条） |
| L01–L02 | Markov 条件 = 充分统计量；MDP/老虎机边界 —— 简报 §5 可加性检验的形式化依据 | 强，需现推 |
| L03 | 重要性采样；「终局奖励下 PDIS 算术上等同轨迹 IS」 | 强，需现推 |
| L05 | 致命三件套 —— FQE = 自举 + 函数逼近 + 离策略，正是三件套，这是 FQE 会发散的原因 | 强，需现推 |
| L07 | DAGGER 的分布漂移 ↔ 「节点 h 的决策改变 h+1 的输入分布，后续节点不可交换」 | 中 |
| L08–L10 | 基线与方差缩减；TRPO 的保守策略改进 ↔ λ 惩罚与安全改进 | 中 |
| L04、L06 | 弱 —— **留空** | — |

### 3.2 讲级：`data/LNN.thread.json`

```jsonc
{
  "title": "…",
  "arc":   "这一讲整体怎么接上课题（来自 direct_application，中文化）",
  "pitfalls": [{"v": "…", "tag": "已核", "ref": "…"}],
  "ammo":     [{"q": "审稿人会问的", "a": "预案", "tag": "…", "ref": "…"}],
  "papers":   [{"t": "标题", "id": "arXiv id", "why": "与课题的关系"}]
}
```

`pitfalls`/`ammo`/`papers` 直接取自 `bridge-threads.json`，**只做中文化与出处保留，不改写论断**。渲染成该讲的入口卡，读前读后都能单独打开。

### 3.3 标注纪律（新增第四档）

现有三分法【原课】/【补课】/【记号】，加第四档**【科研】**。两条硬规矩：

> **R-S1 · 凡科研格里声称 AFlow 或文献行为的话，必须能指回简报的【已核】条目或 arXiv 行号。【推断】与【待核】必须在页面上显式标出，不许抹平成断言。**

> **R-S2 · 简报里那条自我更正必须原样带进 L16 的科研格**：「AFlow 的搜索不是 UCT-MCTS——没有访问计数，没有置信上界，没有 expectimax/minimax 回传；Backpropagation 只是把 (parent, modification, avgScore) 追加进父节点的经验日志。实为 Boltzmann + uniform 的爬山搜索。」这是最容易被审稿人记账、也最容易在二次转写中被悄悄写回错版本的地方。

英文术语保留原文不译（`deficient support`、`cross-fitting`、`effective sample size` 一类）——用户写论文要用英文。

## 4 · 删掉什么（精确清单）

引擎 `coursekit/reader_template.html` 移除：

- 错题本面板（及顶栏入口）
- 复习模式（及「只复习这些页」按钮、← → 的复习态改写）
- 毕业规则「连着答对两次」
- `rw` / `qw` 双计数
- 错题排序（「还没毕业的在前、最近错得多的更靠前」）
- 页条错题标红、标题告警角标

引擎**保留**：每页 1–2 题 · 立即判 · 错项标红 + 正解点亮 · 选项锁死 · `why` 解释 · 答过状态记忆（换页回来不丢）。

存档形状随之简化：`localStorage["<id>-<tag>quiz"]["起始页#题号"]` 从 `{n,w,r[]}` 降为 `{a:选了哪项}`。课程前缀保留——`file://` 下所有本地页面共用一个 origin，去掉前缀两门课会互相覆盖。一次性迁移段保留并继续删旧键（不删的话「清空全部记录」后下次打开又被复活）。

内容层移除：`L10.json` 第 35–36 页那条 `pts` 里的「作业三会动手做这些。下一次：期中考试」。

自测题的**内容**改造（格式不变，仍四选一）：题目从「这个定义是什么」换成「机制 / 为什么 / 边界」；科研相关的讲增设一类题——**给出用户的 AFlow 设定，问这条结论会怎样**。不改成开放式问答，是因为引擎判不了，而 `why` 那段解释才是真正起教学作用的部分。

## 5 · 加厚的判据（打印数字，不打印「通过」）

抄 ML 那边的做法：把质量差距量成倍数再逐条补。目标 **≥ 400 词/页**——不取 ML 的 650，因为 CS234 页面更稀，大量页是上一页的增量构建。

`build_reader.py` 新增闸门，全部输出实际数字：

- 逐讲密度：`L01  15页有讲解  6210词  414词/页  ✓`
- `quote` 覆盖率 ≥ 有讲解页的 80%
- `tbl` ≥ 每 4 页有讲解 1 张
- `res` 的 `tag` ∈ {已核, 推断, 待核}，`ref` 非空
- 分片合并：片间页码区间不许重叠，**重号直接报错**（静默覆盖会丢整段）

三条口径必须钉死，否则同一个闸门会在不同期给出不可比的数：

1. **「词」的定义就是 §2 那一个**：剥掉 HTML 标签后，按「CJK 单字 + 拉丁单词 + 数字串」计数。`build_reader.py` 必须复用同一个函数，不许另写一份。
2. **密度的分母是「有讲解的页」，不是该讲总页数。** A0 只覆盖 L01 前约 15 页，分母就是 15；未覆盖页不计入，也不算缺陷（精读页本来容忍增量构建页）。
3. **A0 期所有覆盖率类闸门按已覆盖页等比折算**，不按整讲。整讲口径在 A1 补完 L01 时才生效。

`res.ref` 可以指三种出处之一：简报节号（如 `简报 §4a`）、`bridge-threads.json` 的线号加字段（如 `thread0.pitfalls[3]`）、或 arXiv id（如 `2410.10762v4 §3.2`）。三种都算，空值不算。

现有 4 条闸门保留：quiz 键必须是某条 note 的起始页 · `a` 落在 `o` 范围内 · 选项 ≥ 3 · 必须给 `why`。

沿用项目 §14 的检查器纪律：**报告必须打印「量了哪些」**（逐片命中数），**文件数为 0 必须非零退出**。

## 6 · 分片

`data/LNN.a.json`、`.b`、`.c`，按页码区间切。`build_reader.py` 按区间合并。触发阈值：**单文件预计超过 80 KB 就分**——按 §2 的 7.2 KB/千词换算，即约 11,000 词，约 28 页厚内容。实际上加厚后几乎每讲都会超。

`data/LNN.thread.json` 单独一份，不参与页级合并。

`course.json` 仍是讲次元数据的唯一来源（标题、页数、PDF、视频），内容文件里不再存一份。

## 7 · 分期

| 期 | 做什么 | 依据 |
|---|---|---|
| **A0 · 样板** | L01 前约 15 页做到目标密度 + 科研格；L01 讲级主线卡；引擎改造与检查器改造一次做完 | 项目 R7「先做一部当样板，再铺开」。精读页容忍未覆盖页（显示「往前翻一页」），所以半讲就是一个能真打开的页面，用户验形态成本最低。L01 的科研连接正对简报 §5 那个「可能否定 MDP 框架本身」的可加性检验 |

| **B** | L11 L12 L13 L15 L16 从零建 | bridge-threads 三条线在这里整条落地。这五讲恰好是现在缺精读页的五讲 |

### 执行中相对本 spec 的三处改动

1. **切分点从 p15 改到 p19。** p15 虽是 note 边界，但会把「四要素」的①与②③④切开，样板就没有完整概念弧。p19 让 `L01.a` 覆盖「RL 是什么 → 一句话定义 → 四要素」一整段。

### 执行中修掉的既有 bug
